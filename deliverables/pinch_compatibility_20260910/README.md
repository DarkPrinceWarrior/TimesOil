# Model Z: проверка PINCHREG и PINCH

Статус 10 сентября: **эквивалентность tNavigator не доказана; нового ЧДД нет**.
Исходные архивы, прежние графики и производственный образ не изменены.

В архиве Model Z отсутствуют присваивания PINCHNUM, GRIDOPTS задаёт максимум
трёх регионов, PINCHREG содержит две записи `2 /` и пустую запись.
По [руководству OPM 2023.04, стр. 631–636](https://opm-project.org/wp-content/uploads/2023/06/OPM_Flow_Reference_Manual_2023-04_Rev-0_Reduced.pdf)
PINCHNUM по умолчанию равен 1; PINCH задаёт для всего поля критерии,
аналогичные региональным. Поэтому проверяемая гипотеза для этого архива —
`PINCH 2 GAP 1.0E20 TOPBOT TOP /`. Это интерпретация документации,
а не измеренная эквивалентность двух симуляторов.
Определения параметров также сверены в исходниках OPM:
[PINCHREG](https://github.com/OPM/opm-common/blob/master/opm/input/eclipse/share/keywords/000_Eclipse100/P/PINCHREG),
[PINCH](https://github.com/OPM/opm-common/blob/master/opm/input/eclipse/share/keywords/000_Eclipse100/P/PINCH).

[Скрипт исследования](../../scripts/check_model_z_pinch.py) принимает только
закреплённые байты исходного архива и grid-файла. Из сохранённых расчётов базы
и лучшего кандидата копируются проверенные по манифестам входы; единственное
изменение — этот блок в grid-файле. Расписания и прочие входные файлы сохраняются
побайтно. Предусмотрены полный OPM и одинаковая официальная экономика обеих сторон.

Первый запуск на исходном OPM 2026.04 завершился с кодом 134 после генерации
**27 696 pinch-out connections**. Assertion: `EntityRep::setValue`,
`index_arg >= 0`. До расчёта добычи и экономики дело не дошло; кандидат не запускался.
[Протокол](failed-stock-protocol.json), [хеши и ошибка](stock-failure.json).

В исходной сетке отдельно обнаружены **414 полностью схлопнутых ячеек**,
помеченных активными и имеющих явно заданный PORV > MINPV=1 м³.
[Диагностика](collapsed-cells.json). Это соответствует условию известного
[исправления OPM/opm-grid №935](https://github.com/OPM/opm-grid/pull/935),
принятого 4 августа 2026: соединения PINCH к таким ячейкам исключаются,
схлопнутые ячейки рассматриваются как барьеры. Авторы отдельно отмечают,
что это устраняет падение, а поведение требует сравнения с другими симуляторами.
Значит, даже прохождение исправленной версии не закрывает проверку tNavigator.
