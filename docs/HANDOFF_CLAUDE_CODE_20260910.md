## 7. Архитектура и контракты

### Трек 1

```text
Исходная ГДМ + принятая история + ограничения + нормативы
 → Qwen: предложение управлений
 → детерминированный валидатор полного фонда
 → OPM: incumbent и кандидат на весь оставшийся период
 → официальный ЧДД на сопоставимом горизонте
 → выбрать допустимый вариант, принять только текущий месяц
 → физическое следующее состояние + хешированная lineage
 → заключения ролей/критика → следующий месяц
 → полный итоговый график, ЧДД и аудит истории
```

Будущие состояния из planning не становятся наблюдённой историей. Переход `a[t] → s[t+1]`; нельзя суммировать накопленные `step_economics` как независимые месячные ЧДД. Финальный элемент уже содержит итог периода. Технический restart — проверенный full replay, а не произвольная ссылка на чужой результат.

Ключевые Y-файлы в отдельной ветке: `scripts/run_track1_mpc.py`, `scripts/audit_track1_lifecycle.py`, `scripts/run_track1_conversion_search.py`; совместные `src/timesoil/aios/opm.py`, `schedule.py`, `schedule_overlay.py`, `economics.py`, `operating_constraints.py`.

### Трек 2

```text
Offline: закреплённые сценарии → OPM → канонические данные → train / validation / test
Online: известная история + будущие управления + статика/связность
 → Google TimesFM (полный фонд, полный горизонт)
 → ограничения прогноза + официальный ЧДД из прогнозных экономических рядов
 → сравнение ограниченного набора вариантов + предложения Qwen
 → зафиксировать график, веса, прогноз, критерий и входы
 → записать единственную попытку финальной верификации
 → OPM + официальный ЧДД → аудит, без повторного выбора
```

## 8. Что именно прогнозирует Google TimesFM

Google TimesFM 3.0 PyTorch, revision **`43046b85ec22d584a13f8098c2ed39c889e129c2`**. Последнее обучение — **полная модель**, `330858048` обучаемых параметров, backbone не заморожен; слово `head` в именах CLI/файлов не означает обучение только последнего слоя.

Контекст: 128 прошлых месяцев. Горизонт: 224 будущих. Весь фонд 103 скважины совместно. На скважину 9 выходов и 6 ковариат; всего 1545 совместных каналов, из них 618 ковариат. Будущие известные воздействия включают rate, target, OPEN, BHP; дополнительно используются роль на границе/информация межскважинного воздействия. Статика включает признаки геологии и комплектации; conditioning первого и последнего слоя включён.

| Выход | Единицы / смысл |
|---|---|
| `WOMR` | Нефть, т/сут |
| `WLPR` | Жидкость, м³/сут |
| `WWIR` | Закачка, м³/сут |
| `THP` | Внутреннее историческое имя: **резервуарная диагностика WBP9, бар**, НЕ устьевое давление |
| `BHP` | Забойное давление, бар |
| `WEFF` | Коэффициент эксплуатации, [0, 1] |
| `WOMT_Diff` | Месячная нефть, т |
| `WLPT_Diff` | Месячная жидкость, т в контракте калькулятора |
| `WWIT_Diff` | Месячная закачка, м³ |

Месячные объёмы — отдельные обучаемые выходы. Не заменять их конечным дебитом × дни. Model Z имеет несколько PVT-регионов; массовые величины формируются с учётом плотностей и соединений. Нельзя произвольно превращать тонны в м³ одной константой или ограничивать массу нефти объёмным ORAT.

В inference неизвестные будущие наблюдения маскируются `NaN`; truth находится отдельно в scoring. Не подключать физическую reference-траекторию из будущего как «помощь» модели. Разделение train/test проверяется по правильным CSV-хешам, не только названиям сценариев.

## 11. Ближайшая проблема Z: OOM в оценке
