# Архитектура Трека 2

## Контуры

1. **Данные и происхождение.** Каждый сценарий связывается с хешами исходной
   модели, расписания и индекса сценариев. Изменившийся вход отклоняется.
2. **Гидродинамика.** OPM Flow запускается последовательно в закреплённом
   контейнерном образе. Выход SUMMARY переводится в каноническую траекторию.
3. **Суррогат.** Физический базис CRM/material balance прогнозирует состояние,
   ансамбль LightGBM учит остатки по нефти, жидкости и давлению.
4. **Неопределённость.** Ансамбль и сценарная калибровка дают интервалы;
   ворота области применимости отбрасывают недопустимую экстраполяцию.
5. **Оптимизация.** Дешёвый поиск ранжирует шестимесячные управления
   добывающих скважин только по суррогату. Покважинная закачка фиксирована на
   базовом расписании. Выбранный кандидат всегда повторно считается в OPM Flow.
6. **Экономика.** Канонический CSV передаётся официальному калькулятору ЧДД;
   суррогатная оценка не считается итоговым ЧДД.
7. **AIOS.** Qwen через API координирует четыре роли и вызывает только
   разрешённые инструменты чтения/валидации. Критик может отклонить план.

## Граница доверия

LLM не получает секреты, не запускает произвольную командную оболочку и не подтверждает
собственный результат. Решение считается пригодным только после проверок
ограничений, повторного расчёта OPM и ЧДД.
