# Комплект Track 2 — Model Z, версия 3

Готовый комплект управляющего расписания для Model Z. По итогам детерминированного поиска выбран кандидат `baseline`: из 32 рассмотренных кандидатов все 32 прошли OOD-фильтр, но ни один не превзошёл базовый сценарий по риск-скорректированному суррогатному прокси. Поэтому улучшение относительно базового управления не заявляется.

## Состав

- `wells_schedule.inc` — управляющие последовательности по скважинам для передачи отдельно;
- `Model_Z_sch.inc` — полная подстановка расписания в исходную модель;
- `lineage.json` — происхождение выбранных действий и хеши входов;
- `manifest.json` — полный манифест поиска, параметры, кандидаты и метрики;
- `submission.json` — машинно-читаемая карточка комплекта и результата;
- `README.md` — эта инструкция.

Это аутентифицированный внутренний replay, но не подтверждение организаторов: `organizer_certified=false`.

## Как использовать

Для подачи управляющих последовательностей используйте `wells_schedule.inc`. Для локального воспроизведения замените `Model_Z/Model_Z_sch.inc` в распакованной модели файлом `Model_Z_sch.inc`, не меняя его содержимое. Точные аргументы запуска, версия образа, хеши входов, результаты OPM и расчёт ЧДД записаны в:

- `../../evidence/model_z_track2_final_replay_a100_v3.json` — встроенный receipt;
- `../../evidence/model_z_track2_final_replay_audit_a100_v3.json` — терминальная проверка всей цепочки.

Перед использованием проверьте комплект:

```bash
sha256sum wells_schedule.inc Model_Z_sch.inc lineage.json manifest.json submission.json
```

## Ограничения

Поиск использовал суррогатный риск-скорректированный прокси, а не официальный ЧДД. Разброс ансамбля суррогатной модели не является конформно откалиброванным интервалом. Управление оптимизировалось на горизонте шести месяцев с 01.01.2007; экономический расчёт выполнялся по полной траектории с 2007 года. Результат получен в OPM Flow, поэтому при сравнении с tНавигатором нужен допуск организаторов на межсимуляторное расхождение.
