# Сдача и финальная валидация (август 2026)

Документ фиксирует правила отбора и проверки решений по материалам организаторов хакатона AIOS.

## Валидационный кейс

На финальной стадии команда получает **валидационный кейс**: набор ограничений и историю разработки месторождения. Модели остаются прежними — **Model Y** для трека 1 и **Model Z** для трека 2; меняются условия задачи, а не само поле и не состав модели.

## Обязательные артефакты

Минимум для проверки:

1. **`wells_schedule.inc`** — расписание управления скважинами, совместимое с гидродинамической моделью без ручной правки после генерации.
2. **Заявленный ЧДД** — значение, рассчитанное по официальной методике.

Полный пакет сдачи обязателен для допуска к валидации:

- исходный код;
- документация;
- инструкция запуска;
- конфигурация и **Docker**.

Без полного пакета валидация не проводится.

## Процедура проверки организаторами

Организаторы выполняют **один полный прогон гидродинамической модели** по сданному `wells_schedule.inc` и сравнивают полученный **ЧДД** с заявленным командой.

- Расхождение заявленного и пересчитанного ЧДД — **дисквалификация**.
- Допускается расхождение порядка **~2 %** из‑за различий симуляторов; это не считается ошибкой команды.
- Выполняется **один расчёт**, повторные прогоны не предусмотрены.

## Рейтинг и финал

- Ранжирование — по **подтверждённому ЧДД** внутри своего трека.
- В финал проходят **лучшие 20 %** допущенных команд по каждому треку, но **не более 10 команд** суммарно.
- Защита: **7 минут** доклад + **5 минут** вопросы.
