# TimesOil → AIOS hackathon: карта возможностей и разрывов

Дата: 2026-08-17. Источники: репозиторий TimesOil, `docs/hackathon/` (бриф, лекции, команды, методика ЧДД).

---

## 1. Что TimesOil уже умеет

**Данные и фонд (Model Y).** Месячная история гидродинамического симулятора tNavigator: 49 скважин (33 добывающие + 16 нагнетательных), 6 блоков по карте разломов, период **2007-05 … 2015-11**. Сырые выгрузки — `raw_data/` (в git не входят): `Dataset.xlsx::MODEL_Y`, широкий Excel «Dataset Шутову АА+», CSV Аленькина, карта разломов `image (5).png`. Оцифровка фонда и блоков — `src/timesoil/wells.py`; загрузка и ловушки данных — `src/timesoil/data.py` (THP = пластовое давление, DobG = жидкость, 2015-12 — мусор, WEFF=0 до пуска скважины).

**Прогноз дебита на 6 месяцев.** Ансамбль Chronos-2 / TiRex-2 / TiDE / LightGBM + физика; на трёх канонических срезах **WAPE 3,74 % по нефти** и **3,21 % по жидкости** (`docs/roadmap.md`, `docs/отчёт_прогноз_дебита_6мес.md`).

**Что TimesOil предсказывает на месяц.** **Нефть и жидкость** — 33 добывающие скважины; один месяц — первый шаг 6-месячного стека, не помесячный цикл МАС хакатона. **Давление** — только в ветке CRM/CRMP с пластовым давлением; BHP добывающих в исходниках Model Y по сути **константа ~60 атм**, не поле давлений ГДМ. **Закачка** — **вход** (16 нагнетательных), не прогнозируемый выход. Это **не** полное состояние ГДМ, **не** цепочка `wells_schedule.inc` → помесячная таблица → ЧДД, **не** суррогат Model Z.

**Физика заводнения.** CRM, двухфазная CRM, CRMP с пластовым давлением, матрица связности по блокам, модель Джентила для обводнённости (`crm.py`, `allocation.py`, `fractional.py`).

**Оптимизация закачки.** `scripts/optimize_injection.py`: SLSQP, сумма закачки фиксирована, перераспределение между 16 нагнетательными; **+2,75 % нефти** (границы ±20 %) и **+4,09 %** (±30 %) за 6 месяцев относительно базового сценария без роста суммарной закачки.

**Перенос на другие полигоны.** UNISIM-I-H и Volve — отдельные контуры, не Model Z.

## 3. Разрывы относительно пакета сдачи AIOS

| Требование хакатона | Статус в TimesOil |
|---------------------|-------------------|
| МАС с LLM в ядре | **Нет** |
| Веб-интерфейс | **Нет** |
| `wells_schedule` под tNavigator / ГГДМ | **Нет** (есть CSV истории, не управляющий график) |
| Расчёт **ЧДД** по организационной методике | **Частично:** пакет `docs/hackathon/chdd/CHDD_PYTHON/` (Python-калькулятор, тесты паритета с веб-версией); интеграции в пайплайн МАС нет |
| Обработка возмущений (остановки, квоты, бурение, перевод в ППД, …) | **Частично:** перевод 15 скважин под нагнетание в 2008 в истории; нет цикла «возмущение → решение → прогон» |
| Суррогат ГГДМ (трек 2) | **Нет** для Model Z; TimesOil **≠** суррогат трека 2 (роль «дешёвый next-state» схожа, но это прогноз дебитов Model Y, не обученный на прогонах ГДМ ~109 скважин) |
| Docker + конфиг + инструкция развёртывания | **Нет** (Docker — только при контейнеризации, §3.4) |

**TimesOil ≠ суррогат трека 2.** Суррогат трека 2 отвечает «что сделает месторождение при таком управлении» на каждом шаге поиска; TimesOil — офлайн-прогноз дебитов по истории Model Y. CRM/CRMP/Джентил — **черновик внутри цикла трека 1**, не замена суррогата Model Z.

**Расхождение горизонта оптимизации.** TimesOil максимизирует прирост нефти на **6 месяцев после 2015-11** (прокси без полной экономики). Хакатон оценивает **NPV/ЧДД** с **01.01.2014** (трек 1) или **01.01.2007** (трек 2) по полной методике (выручка, OPEX, CAPEX, события фонда, дисконт). Прямой перенос `optimize_injection.py` на сдачу даст другой экономический результат.

## 4. Что переиспользовать в решении AIOS

- **Блоки и связность** (`wells.py`, `allocation.py`, CRM по блокам) — пространственная структура Model Y и проверка разломов данными.
- **CRM / CRMP** — черновик гипотез **только внутри цикла МАС трека 1** (до прогона ГГДМ); не суррогат трека 2.
- **Признаки состояния скважины** — давление, обводнённость, дебиты, WEFF; уже отработаны в `data.py` и стеке прогноза.
- **История перевода в закачку** (2008) — эталон логики смены режима добыча → ППД.
- **SLSQP по перераспределению закачки** — шаблон оптимизации при фиксированной сумме воды; целевую функцию нужно заменить на ЧДД/NPV.
- **Стек прогноза 6 мес** — роль «дешёвый next-state» схожа с суррогатом, но TimesOil **≠** суррогат трека 2 (Model Y, не Model Z; не обучен на прогонах ГДМ организаторов).

## 6. Практический порядок (кратко)

1. Сверить ЧДД на базовом сценарии Model Y через `CHDD_PYTHON`.
2. Реализовать writer/reader `wells_schedule.inc` для tNavigator.
3. Собрать МАС (координатор + агенты фонда/ППД/ограничений), не «агент на каждую скважину».
4. Трек 1: цикл через ГГДМ, CRM — внутренний черновик. Трек 2: суррогат Model Z + финальная проверка ГГДМ.
5. Веб-UI с LLM и слой интерпретируемости — обязательны по ТЗ §3.1; Docker — только при контейнеризации (§3.4).
