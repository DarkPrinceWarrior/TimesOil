## Онбординг — must know

- **Цель:** МАС управляет разработкой месторождения; максимизировать **NPV** при соблюдении ограничений.
- **Выход:** `wells_schedule` + заявленный NPV + **обязательный UI** с LLM в ядре.
- **Цикл МАС:** оценка состояния → решение → управляющее воздействие → пересчёт (ГГДМ или суррогат).
- **Трек 1:** исторический ориентир онбординга — ~46 скв.; фактический deck Model Y — **49**. ГГДМ на каждой итерации.
- **Трек 2:** исторический ориентир онбординга — ~100 скв.; фактический deck Model Z — **103 уникальные**. Суррогат для поиска, ГГДМ — финал.
- **Возмущения:** остановки, ОПЕК, обводнённость, ППД, инфраструктура, новые/переводимые скважины.
- **Валидация:** организаторы пересчитывают на ГГДМ; **расхождение NPV = дисквалификация**.
- **Отбор в финал:** топ 20% по NPV (макс. 10 команд); нужен полный пакет (код, git, docs, schedule).
- **Защита:** 7 мин презентация + 5 мин вопросы; демо живого запуска.
- **Сдача:** Docker, конфиг, seed, воспроизводимость; без ручной «магии».

## Лекция «Методы» — must know

- DL — «чёрный ящик» f: X→Y; обучение = минимизация ошибки (градиентный спуск).
- **Train/val/test** и утечки: перемешать до split; аугментация — после split.
- **RNN→LSTM→Transformer:** последовательности; attention даёт параллелизм и дальние связи.
- **Интерпретируемость:** attention maps полезны, но ≠ причинное объяснение; CoT не гарантирует «faithful» рассуждение.
- **Суррогат:** быстрая замена ГГДМ; данные генерируются DoE (LHS и т.п.); риск **экстраполяции** за пределы обучения.
- PINN / hybrid — физика в loss или поправка к упрощённой модели.
- **RL:** MDP, награда (NPV/КИН); PPO для непрерывного управления; **дизайн награды** — критичен (reward hacking).
- Суррогат часто = «быстрая среда» для RL; политика может не перенестись на реальный симулятор.
- **МАС:** не «агент на скважину» без координации — нестационарность, credit assignment, физическая связность.
- Парадигмы: CTDE, value decomposition (VDN/QMIX), иерархия, коммуникация между агентами.
- Лекция даёт **инструментарий**, не готовую архитектуру — команда проектирует сама.

## Лекция «Разработка» (Алёнкин) — must know

- Разработка — **единая динамическая система**: локальное изменение режима одной скважины меняет давления и потоки по всему объекту.
- **ФЕС** (пористость, проницаемость, нефтенасыщенность, Hэф) задают запасы, дебиты и схему сетки.
- **Дарси, ОФП, подвижность фаз** — основа фильтрации; M>1 → неустойчивый фронт, viscous fingering.
- **ППД:** цели — фронт вытеснения, компенсация, давление, согласование с инфраструктурой (КНС, парки).
- **Kкомп** (компенсация) — не единственный KPI; смотреть вместе с Pпл, WCT, профилями приёмистости.
- **Прорывы воды:** каналы высокой k, форсирование, неблагоприятный mobility ratio, конусообразование.
- **Диагностика:** лаги «закачка→добыча», рост WCT без Qн, падение Pпл, «холостая» закачка.
- **Цифровой контур:** мониторинг → анализ → прогноз (ГГДМ/суррогат) → оптимизация → контроль; не подменять физику.
- **Трек 1 / модель Y:** 49 скв., 16 нагнет., 3 разлома; цикл оценка→режим→**расчёт ГГДМ**.
- **Трек 2 / модель Z:** 103 уникальные скважины (92 добывающих и 41 нагнетательная когда-либо, 30 со сменой роли); согласованные решения на уровне объекта; **суррогат/NN** для ускорения.
- **Целевая функция:** max ЧДД (NPV) при ограничениях по пласту, инфраструктуре, ППД и воспроизводимости.
