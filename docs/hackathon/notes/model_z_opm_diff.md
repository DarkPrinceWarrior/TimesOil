### Ключевые слова: что убрали / добавили

| Только в **old** | Только в **final OPM** |
|------------------|------------------------|
| **WELLTRACK** (103 блока) — траектории стволов | **COMPDAT** (60 блоков, ~31 800 строк перфораций) |
| **COMPDATMD** — перфорации по MD | — |

**Интерпретация:** tNavigator хранил траектории (`WELLTRACK`) и перфорации по измеренной глубине (`COMPDATMD`). Для OPM Flow траектории вынесены/не нужны в deck, перфорации заданы классическим **`COMPDAT`** по IJK — стандартный Eclipse-формат.

Разница **−1** в WCONINJE/WCONPROD — следствие перестройки одного временного шага при конвертации, не смена фонда скважин.

### HEAD расписания

- **Old:** сразу `RPTSCHED`, затем **`WELLTRACK '1'`** с длинной таблицей X/Y/Z/MD.
- **Final:** `RPTSCHED`, затем единый блок **`WELSPECS`** на 103 добывающие скважины и **`COMPDAT`** вместо WELLTRACK/COMPDATMD.

## Практические выводы

1. **Прогон трека 2:** `Model_Z_final_OPM.zip` + **OPM Flow** (или согласованный Eclipse-reader).
2. **Старый zip** нужен только если сравниваете поведение tNavigator (WELLTRACK/COMPDATMD) vs OPM.
3. **Сетку и edit** не меняли геометрию DIMENS; правки grid — удаление tNavigator-only `ARRZONE*`.
4. **Обучающие прогоны для суррогата** организаторы не поставляют — генерируйте прогонами final OPM на своих `wells_schedule.inc`.
