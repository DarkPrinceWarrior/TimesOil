# Разбор с командой (17.08.2026)

Согласованная картина после разбора ТЗ в чате. Официальная команда scorp — **трек 2**; **TimesOil** заточен под **Model Y** (**трек 1**).

## Одно ТЗ, два трека

Оба трека: мультиагентная система + языковая модель в ядре + слой объяснений + простой интерфейс. Выход: `wells_schedule.inc` + заявленный ЧДД.

**Трек 1:** каждый месяц — полный ГДМ (Model Y меньше по масштабу). Агенты решают **действия**, ГДМ считает физику. **tNavigator** не прогнозирует и не считает деньги.

**Трек 2:** тот же цикл, но на этапе поиска ГДМ заменяет суррогат. Суррогат обучают на **своих** прогонах ГДМ — организаторы дампов не дали. Один полный ГДМ выбранного целого расписания — для числа, которое заявляете.

## Как проверяют

**Этап 1:** участник прогоняет тестовый кейс, сдаёт расписание + заявленный ЧДД. Ранжирование по заявленному ЧДД. В следующий этап — топ 20 %, не более 10 команд.

**Этап 2:** организаторы **один** раз прогоняют ваш `wells_schedule.inc` через ГДМ, тот же **CHDD_PYTHON**. Расхождение с заявленным ЧДД — дисквалификация. ~2 % «люфта» симулятора — из канала обсуждения, не из текста ТЗ. Защита 7+5 минут — онбординг, не лимит из ТЗ.

Тестовый кейс ≠ Model Y / Model Z. Y и Z — месторождения. Тестовый кейс — те же поля, но с **другими** ограничениями и, возможно, изменённой историей.

Разметки «правильный ответ» нет. «Правильного расписания» нет.

Организаторы не ставят агентов на «другую базу». То же поле, другие условия. Они перезапускают **ваше** расписание, а не ваше обучение.

## Откуда ЧДД

Две машины: **ГДМ** (tNav / OPM Flow) → помесячная таблица (нефть, жидкость, закачка, давления). **CHDD_PYTHON** → одно число (млн руб). **tNavigator** ЧДД не печатает.

Калькулятор можно запустить без tNav, если таблица уже есть — но заявлять это число честно можно только если таблица получена из ГДМ **вашего** расписания.

Сдаваемый артефакт расписания — `wells_schedule.inc`, не CSV расписания. CSV/xlsx — вход калькулятора (экспорт симулятора).

## Трек 1 на Model Y, простыми словами

История до **2014-01** — стартовое состояние. Деньги считаются с **01.01.2014**. Горизонт архива ~23 месяца до **2015-11**.

33 добывающих + 16 нагнетательных, 6 блоков A / B / B2 / C / D / E. Скв. 1 полностью обводнена. Скв. 19 — нагнетатель с начала; 15 скважин переведены в нагнетание в 2008.

Каждый месяц: агенты видят состояние → задают управление → tNav продвигает на месяц → новое состояние. И так по кругу. Это **не** 6-месячный прогноз TimesOil.

Блочные агенты + оркестратор — нормальная архитектура, ТЗ её не требует.

**Не** сравнивать симулированную траекторию 2014–2015 с историческими фактами. История — чужое базовое расписание. Оценка — ЧДД **вашего** прогона.

Текущий Y без ограничений — песочница для физики, не эталон для сдачи. В тестовом кейсе изменят историю до точки X и добавят лимиты по воде.

## Трек 2

Тот же помесячный цикл. Суррогат отвечает: «что сделает месторождение при таком управлении». Промежуточный ЧДД по суррогату — черновик. Финал: один полный ГДМ на весь горизонт → **CHDD_PYTHON**.

TimesOil **не** является этим суррогатом (см. `timesoil_map.md`).
