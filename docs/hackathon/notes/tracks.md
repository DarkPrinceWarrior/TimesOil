# Трек 1 и трек 2

**Одно ТЗ, два трека** — участник выбирает один. Оба решают задачу оптимального управления разработкой: максимизация **NPV (ЧДД)** при соблюдении технологических ограничений. Итог — **`wells_schedule.inc`** и заявленное значение NPV.

Различаются масштаб модели и место полного прогона гидродинамической модели (ГДМ) в цикле мультиагентной системы (МАС).

| Параметр | Трек 1 · Model Y | Трек 2 · Model Z |
|----------|------------------|------------------|
| **Модель** | Model Y (49 скважин, 16 нагнетательных, разломы; сетка 49×47×141) | Model Z (103 уникальные скважины: 92 добывающих и 41 нагнетательная когда-либо, 30 со сменой роли; сетка 91×102×59; архив **Model_Z_final_OPM**) |
| **Старт учёта ЧДД** | **01.01.2014** | **01.01.2007** |
| **История модели** | tNavigator, START 01 MAY 2007 | tNavigator 25.1, START 01 JUN 1991 |
| **ГДМ в цикле МАС** | **Полный прогон на каждой итерации** | **Суррогат** в переборе; полная ГДМ — **финальная проверка** кандидата |
| **Фокус оценки** | Корректность МАС при жёстких ограничениях | Корректность + масштаб поля + скорость и качество суррогата |
| **Сдача сверх общего пакета** | `wells_schedule.inc` + заявленный ЧДД | То же + суррогат и метрики его качества (WAPE и др.) |

## Общие требования (оба трека)

По [ТЗ](../extracted/tz.md) и [посту канала](../extracted/official_post.md):

- **LLM в ядре агентов** — обязательна (языковая или мультимодальная модель в слое принятия решений).
- **Слой интерпретируемости** — объяснение действий агентов.
- **Простой графический интерфейс** — взаимодействие с МАС и разбор результатов.
- **Управляющие воздействия**: открытие и закрытие скважин; изменение режимов работы; иные допустимые воздействия по постановке задачи.
- **Цикл МАС**: оценка состояния → решение → управляющее воздействие → повторная оценка. Без ручного вмешательства после запуска.
- **Воспроизводимость** на тестовом кейсе организаторов.

## Общий пакет сдачи

- исходный код, документация, инструкция запуска;
- файл конфигурации;
- **Docker-образ или материалы для сборки** — *если используете контейнеризацию* (в онбординге рекомендовали для воспроизводимости; по ТЗ — при контейнеризации);
- **`wells_schedule.inc`** без ручной доработки после генерации;
- заявленный ЧДД по методике **`CHDD_PYTHON`**;
- демонстрация на защите **7 + 5** мин.

Подробности проверки и отбора — [submission.md](submission.md). Симуляторы и открытые полигоны — [simulators.md](simulators.md).

## Цикл трека 1 на Model Y

**Фонд:** 33 добывающих + 16 нагнетательных. Нагнетательные: **2, 4, 7, 13, 15, 19, 21, 24, 26, 28, 32, 34, 36, 37, 41, 42**. Скв. **19** — нагнетатель с начала; **15 скважин** переведены из добычи в **2008-02 … 2008-07**.

**Блоки:** A / B / B2 / C / D / E. Пример блока **C**: добывающие **1, 12, 16, 20, 29, 49, 52**; нагнетательные **4, 21, 32**. Скв. **1** полностью обводнена.

**Горизонт и деньги:** учёт ЧДД с **01.01.2014**; в текущем архиве ~**23** месяца до **2015-11**. Подробности проверки и контекст — [dialog.md](dialog.md); методика и запуск **`CHDD_PYTHON`** — [npv.md](npv.md).

**Помесячный цикл (нумерованный):**

1. Агенты оценивают текущее состояние поля.
2. Агенты формируют управление → **`wells_schedule.inc`** (или его актуальный фрагмент на месяц).
3. **Полный прогон ГДМ** (tNavigator, Model Y) на один месяц вперёд.
4. Новые строки в помесячной таблице (добыча, закачка, давления).
5. Повтор с п. 1 до конца горизонта.
6. Итоговая таблица → **`CHDD_PYTHON --start-year 2014`** → заявленный ЧДД.

**Важно:**

- Агенты **не прогнозируют** дебиты и давления — они выбирают **действия** (открытие/закрытие, режимы).
- **ГДМ — не прогнозатор** и не «модель TimesOil»; это физический симулятор, который считает последствия ваших воздействий.
- **Не** подгоняйте цикл под совпадение с Excel-историей **2014–2015** — это прошлое, не цель оптимизации.
- Агенты по блокам + оркестратор — **опциональная** архитектура, не требование ТЗ.
- В текущей модели **нет технологических ограничений** (песочница); на тестовом кейсе организаторов ограничения будут другими — см. [dialog.md](dialog.md).

## Цикл трека 2

Тот же логический цикл МАС, что в треке 1, но на этапе **перебора** вместо полного ГДМ на каждой итерации используется **суррогат**.

**Суррогат:**

- Обучается командой **самостоятельно** на **своих** прогонах ГДМ модели **`Model_Z_final_OPM`** (OPM Flow). Организаторы готовых дампов не предоставляют.
- **TimesOil** — отдельный контур прогноза дебитов для Model Y; **не** является суррогатом трека 2.

**Цикл поиска и финальная проверка:**

1. На суррогате — **много** полных расписаний (быстрая оценка кандидатов).
2. Лучший кандидат → **один** полный прогон ГДМ (**`Model_Z_final_OPM`**) на всё расписание целиком.
3. Таблица из финального прогона → **`CHDD_PYTHON --start-year 2007`** → заявленный ЧДД (см. [npv.md](npv.md)).
4. Сдача: **`wells_schedule.inc`** + заявленный ЧДД + суррогат и метрики его качества (WAPE и др.).

Контекст проверки организаторами и различия треков — [dialog.md](dialog.md).
