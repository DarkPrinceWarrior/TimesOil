# ЧДД (NPV) — официальный калькулятор AIOS и методика расчёта

Документ описывает **официальный** Python-калькулятор организаторов хакатона AIOS и **официальную** методику расчёта чистого дисконтированного дохода (ЧДД). Для оценки решений организаторы используют **именно этот** калькулятор; расхождение с их пересчётом — основание для дисквалификации (допускается только ~2 % погрешность симулятора).

Исходники:
- Калькулятор: `docs/hackathon/chdd/CHDD_PYTHON/` (версия ядра `7.0.2-negative-row-filter`)
- Методика: `docs/hackathon/sources/Методика_расчета_ЧДД_скорректированная.docx` → `docs/hackathon/extracted/npv_corrected.md`

## Две машины

**ГДМ** (tNavigator / OPM Flow) по вашему `wells_schedule.inc` выдаёт **месячную таблицу** — добычу, закачку, давления по скважинам. **CHDD_PYTHON** по этой выгрузке считает **ЧДД в млн руб.**; других калькуляторов на финале нет.

Заявить ЧДД без таблицы, полученной прогоном **вашего** расписания через ГДМ, нельзя: организаторы на финале сами гоняют симулятор и сверяют пересчёт с заявкой — расхождение это **дисквалификация**. Подробнее: [dialog.md](dialog.md).

## Как запустить

### Linux / WSL (через закреплённое окружение TimesOil)

`openpyxl>=3.1` закреплён в `pyproject.toml` и `uv.lock`. Поддерживаемый запуск
из корня репозитория использует только это окружение:

```bash
cd /home/ruslan_safaev/TimesOil
uv sync --locked
uv run python docs/hackathon/chdd/CHDD_PYTHON/РАСЧЕТ_ЧДД.py
```

Трек 1 (старт дисконтирования с 2014):

```bash
uv run python docs/hackathon/chdd/CHDD_PYTHON/РАСЧЕТ_ЧДД.py --start-year 2014
```

Трек 2 (старт с 2007):

```bash
uv run python docs/hackathon/chdd/CHDD_PYTHON/РАСЧЕТ_ЧДД.py --start-year 2007
```

Входной файл выбирается через `ВХОДНОЙ_ФАЙЛ.txt` либо явным `--input`. Не
устанавливать зависимости вручную через `pip` и не использовать `uv run --with`:
это обходит воспроизводимость `uv.lock`.

Результат: `output/Расчет_ЧДД_<имя_входного_файла>.xlsx`. Опционально `--json путь.json` для машиночитаемого дампа.

## WLPR, WWIR и события (events)

### Действующий фонд

Скважина **действующая**, если `WLPR > 0` **или** `WWIR > 0`. Остановленная (`WLPR = 0` и `WWIR = 0`) в фонд не входит; затраты на содержание по ней не начисляются.

### WLPR (деbit жидкости)

- Определяет режим добывающей скважины и подбор ЭЦН.
- **Лимит методики:** `WLPR > 500` м³/сут — ошибка расчёта (калькулятор бросает `ValueError`).
- Смена ЭЦН: при выходе за верхнюю границу — upsize на минимальный подходящий насос; downsize — только если `WLPR` упал более чем на **100** м³/сут ниже нижней границы текущего насоса (`downsizeThreshold`, зафиксирован в коде).

### WWIR (приемистость)

- Определяет режим нагнетательной скважины.
- Перевод **добывающей → нагнетательная**: на предыдущем шаге была добыча (`WLPR > 0` или `WOMR > 0`), на текущем — закачка (`WWIR > 0`, добыча = 0). Стоимость перевода **5,0 млн руб.** в OPEX; отдельная «остановка» при прямом переводе **не** начисляется.

### События остановки / запуска

Сравнивается активность соседних месяцев (`WLPR > 0` или `WWIR > 0`):

| Событие | Условие | Стоимость |
|---------|---------|-----------|
| **stop** | Был активен → стал неактивен | 1,0 млн руб. |
| **start** | Был неактивен → стал активен | 1,0 млн руб. |

Запуск **не** требует нового ЭЦН; CAPEX насоса — только при смене типоразмера
по правилам. Начальный парк учитывается одним из двух явных экономических
профилей:

| Профиль | `chargeInitialPump` | Когда применять |
|---|---:|---|
| `organizer_reference` | `true` | Полная история от старта deck для сверки с базовым расчётом организаторов |
| `operational_sunk_assets` | `false` | Оптимизационный горизонт: ЭЦН, установленные до его начала, уже оплачены |

Профиль и эффективные нормативы записываются в provenance расчёта; не менять
флаг неявно между baseline и кандидатом.

### Смена ЭЦН

- OPEX операции: **1,8 млн руб.** за смену.
- CAPEX: стоимость нового насоса по таблице ЭЦН.

## Старт дисконтирования по трекам

| Трек | Дата начала управления / дисконтирования |
|------|------------------------------------------|
| **Трек 1** | **01.01.2014** (`--start-year 2014`) |
| **Трек 2** | **01.01.2007** (`--start-year 2007`) |

Коэффициент дисконтирования для стартового года = **1**. Далее: `1 / (1 + WACC)^n`, где `n` — число лет от стартового. WACC по умолчанию **10 %**.

Без `--start-year` калькулятор берёт **минимальную дату** в данных (первый год в файле).

## Правила методики

- `WOMT_Diff` — т, `WLPT_Diff` — т, `WWIT_Diff` — м³
- нормативы фиксированы на весь горизонт
- `WLPR` не более 500 м³/сут
- остановка и запуск — два отдельных события по 1,0 млн руб.
- перевод под закачку — 5,0 млн руб. (без стоимости ЭЦН)
- начальный ЭЦН учитывается только по явно выбранному профилю
  `organizer_reference` / `operational_sunk_assets`
- отрицательные `WLPT_Diff` / `WOMT_Diff` / `WWIT_Diff` выкидывают всю месячную строку

---

## Правило отрицательных строк (важно для симулятора)

Если **хотя бы одно** из `WLPT_Diff`, `WOMT_Diff`, `WWIT_Diff` **отрицательно**, строка **полностью исключается** из экономического расчёта (не только нефть — вся строка: добыча, закачка, фонд, события, FCF, ЧДД). Версия калькулятора явно помечена: `7.0.2-negative-row-filter`.
