# ЧДД (NPV) — официальный калькулятор AIOS и скорректированная методика

Документ описывает **официальный** Python-калькулятор организаторов хакатона AIOS и **скорректированную** методику расчёта чистого дисконтированного дохода (ЧДД). Для оценки решений организаторы используют **именно этот** калькулятор; расхождение с их пересчётом — основание для дисквалификации (допускается только ~2 % погрешность симулятора).

Исходники:
- Калькулятор: `docs/hackathon/chdd/CHDD_PYTHON/` (версия ядра `7.0.2-negative-row-filter`)
- Старая методика: `docs/hackathon/sources/Методика_расчета_ЧДД.docx` → `docs/hackathon/extracted/npv_old.md`
- Скорректированная: `docs/hackathon/sources/Методика_расчета_ЧДД_скорректированная.docx` → `docs/hackathon/extracted/npv_corrected.md`

## Как запустить

### Windows

1. Положить `.xlsx` или `.csv` с исходными данными в `chdd/CHDD_PYTHON/input/`.
2. В `ВХОДНОЙ_ФАЙЛ.txt` указать **одну строку** — только имя файла (без пути).
3. Проверить `input/Нормативы_ЧДД.xlsx`.
4. Запустить `ЗАПУСК_WINDOWS.bat` (ставит `openpyxl` через `pip`, если нужно).

### Linux / WSL (через uv проекта TimesOil)

Зависимость калькулятора — только `openpyxl`; в `pyproject.toml` TimesOil её нет, поэтому используется ephemeral-зависимость:

```bash
cd /home/ruslan_safaev/TimesOil/docs/hackathon/chdd/CHDD_PYTHON
echo "Пример_исходных_данных.xlsx" > ВХОДНОЙ_ФАЙЛ.txt
cd /home/ruslan_safaev/TimesOil
uv run --with openpyxl python docs/hackathon/chdd/CHDD_PYTHON/РАСЧЕТ_ЧДД.py
```

Трек 1 (старт дисконтирования с 2014):

```bash
uv run --with openpyxl python docs/hackathon/chdd/CHDD_PYTHON/РАСЧЕТ_ЧДД.py --start-year 2014
```

Трек 2 (старт с 2007):

```bash
uv run --with openpyxl python docs/hackathon/chdd/CHDD_PYTHON/РАСЧЕТ_ЧДД.py --start-year 2007
```

Альтернатива с `.venv` TimesOil (если `openpyxl` уже установлен в окружение вручную):

```bash
/home/ruslan_safaev/TimesOil/.venv/bin/python docs/hackathon/chdd/CHDD_PYTHON/РАСЧЕТ_ЧДД.py --start-year 2014
```

Результат: `output/Расчет_ЧДД_<имя_входного_файла>.xlsx`. Опционально `--json путь.json` для машиночитаемого дампа.

## WLPR, WWIR и события (events)

### Действующий фонд

Скважина **действующая**, если `WLPR > 0` **или** `WWIR > 0`. Остановленная (`WLPR = 0` и `WWIR = 0`) в фонд не входит; затраты на содержание по ней не начисляются.

### WLPR (деbit жидкости)

- Определяет режим добывающей скважины и подбор ЭЦН.
- **Лимит методики:** `WLPR > 500` м³/сут — ошибка расчёта (калькулятор бросает `ValueError`).
- Смена ЭЦН: при выходе за верхнюю границу — upsize на минимальный подходящий насос; downsize — только если `WLPR` упал более чем на **100** м³/сут ниже нижней границы текущего насоса (`downsizeThreshold`, зафиксирован в коде).

### WWIR (приемистость)

- Определяет режим нагнетательной скважины.
- Перевод **добывающей → нагнетательная**: на предыдущем шаге была добыча (`WLPR > 0` или `WOMR > 0`), на текущем — закачка (`WWIR > 0`, добыча = 0). Стоимость перевода **5,0 млн руб.** в OPEX; отдельная «остановка» при прямом переводе **не** начисляется.

### События остановки / запуска

Сравнивается активность соседних месяцев (`WLPR > 0` или `WWIR > 0`):

| Событие | Условие | Стоимость |
|---------|---------|-----------|
| **stop** | Был активен → стал неактивен | 1,0 млн руб. |
| **start** | Был неактивен → стал активен | 1,0 млн руб. |

Запуск **не** требует нового ЭЦН; CAPEX насоса — только при смене типоразмера по правилам. Первичное оснащение при старте сценария **бесплатно** (`chargeInitialPump = false` по умолчанию).

### Смена ЭЦН

- OPEX операции: **1,8 млн руб.** за смену.
- CAPEX: стоимость нового насоса по таблице ЭЦН.

## Старт дисконтирования по трекам

| Трек | Дата начала управления / дисконтирования |
|------|------------------------------------------|
| **Трек 1** | **01.01.2014** (`--start-year 2014`) |
| **Трек 2** | **01.01.2007** (`--start-year 2007`) |

Коэффициент дисконтирования для стартового года = **1**. Далее: `1 / (1 + WACC)^n`, где `n` — число лет от стартового. WACC по умолчанию **10 %**.

Без `--start-year` калькулятор берёт **минимальную дату** в данных (первый год в файле).

## Правило отрицательных строк (важно для симулятора)

Если **хотя бы одно** из `WLPT_Diff`, `WOMT_Diff`, `WWIT_Diff` **отрицательно**, строка **полностью исключается** из экономического расчёта (не только нефть — вся строка: добыча, закачка, фонд, события, FCF, ЧДД). Версия калькулятора явно помечена: `7.0.2-negative-row-filter`.

## Отличия: старая vs скорректированная методика

| Тема | Старая (`npv_old.md`) | Скорректированная (`npv_corrected.md`) | Почему важно |
|------|----------------------|------------------------------------------|--------------|
| **Единицы месячных объёмов** | Неявно («Q в тыс. м³» для закачки) | Явно: `WOMT_Diff` — т, `WLPT_Diff` — т, `WWIT_Diff` — м³ | Исключает путаницу т/м³ при подготовке CSV из симулятора |
| **Цены и нормативы по годам** | «Могут задаваться отдельно по каждому году» | **Фиксированы** на весь горизонт до последнего шага | Упрощает сравнение сценариев; калькулятор так и работает |
| **Лимит WLPR** | Не указан | **Не более 500 м³/сут** | Нереалистичный дебит → отказ расчёта |
| **Остановка / запуск** | Кратко «по смене состояния» | Два **отдельных** платных события по 1,0 млн; при остановке скважина вне фонда | Влияет на OPEX фонда и event-cost; в коде — `startStopCount` |
| **Перевод под закачку** | **5,0 + стоимость ЭЦН** | **Только 5,0** млн руб. | Старый текст завышал OPEX перевода; код использует 5,0 без CAPEX насоса |
| **Первичный ЭЦН** | Не описан | По умолчанию **не начисляется**; опция `chargeInitialPump` | Стартовый CAPEX не штрафует за уже работающий фонд |
| **Налоги и амортизация** | Формулы без детализации | Амортизация в taxable profit (0 по умолчанию); имущество в OPEX; прибыль в FCF | Согласовано с `compute_calculation` |
| **Отрицательные месячные объёмы** | Не описано | В коде: **полное исключение строки** | Критично при выгрузке из симулятора (технические коррекции) |

**Практический вывод:** для хакатона ориентироваться на **скорректированную** методику и **официальный** Python-калькулятор v7.0.2; сверять итоговый `totalChddM` и `profitabilityIndex` до отправки решения.
