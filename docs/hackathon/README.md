## Что сдавать на отбор в финал

Организаторы присылают валидационный кейс: ограничения и история. Объект не меняется: трек 1 — Model Y, трек 2 — Model Z.

Передать:

1. `wells_schedule.inc` — график управления, читается моделью без ручной правки.
2. Заявленное значение чистого дисконтированного дохода на этом кейсе.
3. Полный пакет: код, документация, инструкция запуска, конфигурация / Docker. Без пакета к проверке не допускают.

Проверка: один прогон полной гидродинамической модели на вашем расписании. Расхождение с заявленным доходом — дисквалификация. Допуск около 2 % из‑за разницы симуляторов. Повторных прогонов нет.

В финал — 20 % лучших внутри трека, не больше 10 команд. Защита: 7 минут + 5 минут вопросов.

## Официальный расчётчик дохода

Каталог: [chdd/CHDD_PYTHON](chdd/CHDD_PYTHON). Методика: `sources/Методика_расчета_ЧДД_скорректированная.docx` (заменяет прежнюю). Команды: [notes/chdd_usage.md](notes/chdd_usage.md).

Положить вход в `input/`, указать имя в `ВХОДНОЙ_ФАЙЛ.txt`, проверить `Нормативы_ЧДД.xlsx`, запустить `РАСЧЕТ_ЧДД.py`. Пример выхода — Excel и JSON в `output/`.

Отрицательные `WLPT_Diff` / `WOMT_Diff` / `WWIT_Diff` выкидывают всю месячную строку из экономики. Контроль на полном CSV: 4418.1319744583 млн руб. Автотесты калькулятора: 14 прошли, 2 пропущены (паритет с веб-ядром, нужен Node).

Что поменяли в методике относительно первой версии: перевод под закачку — только 5,0 млн (без стоимости ЭЦН); жёсткий потолок `WLPR ≤ 500` м³/сут; нормативы фиксированы на весь горизонт; стоп и старт — два события по 1,0 млн; первый ЭЦН по умолчанию бесплатен.
