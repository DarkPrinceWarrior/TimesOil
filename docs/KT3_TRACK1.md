# Трек 1 / Model Y — подготовка к КТ3

Ветка поставки: `track-1-model-y`. Режим `--agent` использует внешний
Cerebras `qwen-3.8-27b`: координатор → аналитик → планировщик выбирают один
типизированный вариант для текущего состояния; полный OPM Flow и официальный
ЧДД проверяют его; критик проверяет результат перед переходом к следующему
месяцу. Локальная LLM не используется.

## Запуск полного расчёта на Linux / A100

Нужны Python 3.13 / uv, Docker CLI с доступом к Docker Engine, исходная модель,
аутентифицированный начальный restart и конфигурация кейса. OPM запускается
отдельным контейнером с закреплённым digest из кода. `uv sync --locked`
устанавливает зависимости из поставки; дополнительных пакетов для нового
режима не требуется.

```bash
export LLM_BASE_URL=https://api.cerebras.ai/v1
export LLM_MODEL=qwen-3.8-27b
export LLM_MAX_OUTPUT_TOKENS=4096
export LLM_TIMEOUT_SECONDS=180
export LLM_API_KEY="$(cat "$QWEN_API_KEY_FILE")"
uv run python scripts/run_track1_mpc.py /absolute/path/case.json \
  --runs-dir /absolute/path/new-result-directory --agent
```

При необходимости `LLM_PROXY_URL` задаёт HTTP(S) CONNECT-прокси. Проверенный
маршрут A100 использует обратный SSH-туннель к прокси WSL; для такого маршрута
WSL, прокси и туннель должны оставаться доступны. Ключ не включается в git,
конфигурацию кейса, агентный контекст или квитанции.

В `case.json` используется существующая схема
`timesoil.aios.track1-mpc-input/v1`:

- `case.start` и `case.end` — первый и последний месяцы управления включительно;
- `case.economics_start` — начало периода управления;
- `initial_state.month` — первый месяц, `restart_ref` — проверенный manifest
  начального состояния с `#sha256=...`;
- `case.producers`, `case.injectors` и месячные `candidates` — фактический фонд
  и полные допустимые варианты управления всеми скважинами;
- `opm.source`, `deck`, `schedule_include` — исходные файлы именно этого кейса;
- `opm.runs_dir` и `--runs-dir` — новые каталоги для каждого эксперимента.

Банк кандидатов должен учитывать новые ограничения организаторов. Планировщик
может выбрать только индекс существующего варианта; произвольные текстовые
команды не исполняются. Перед LLM варианты проходят `ScheduleCompiler`, после
выбора сохраняются обязательные проверки полного OPM, ЧДД и lineage.

Выход: `wells_schedule.inc`, `result.json`, `manifest.json`, `manifest.sha256`.
При `--agent` в `result.json` включены модель, адрес API, время выполнения и
решения всех четырёх ролей по месяцам. Отдельный `*-agent.jsonl` записывается
после каждой фазы и сохраняет диагностику при отказе. Ошибка провайдера,
недопустимый индекс, отказ планирования/критика или ошибка численных проверок
останавливает цикл. Готовой поставки при незавершённом цикле нет.

`run_id` группирует одинаковые входные данные; точный результат идентифицируют
SHA-256 результата и manifest. Решения LLM могут различаться между запусками.
Каталоги предыдущих запусков не перезаписываются.

## Сборка API

```bash
docker compose build
docker compose up -d --wait
```

`QWEN_API_KEY_FILE` должен указывать на файл, читаемый UID 10001. Конфигурация
по умолчанию — `config/aios.env`; заменить её можно через `AIOS_ENV_FILE`.
API работает без root, с read-only корнем и без Docker socket. Полный OPM-цикл
выполняется приведённой выше командой на хосте. API-образ также содержит CLI
`scripts/run_track1_mpc.py`, но сам по себе не предоставляет Docker Engine.
Для A100 с loopback-прокси есть `compose.a100.yaml`, порт по умолчанию 18083.

## Объём проверки и ограничения

Историческая поставка КТ2 сохранена в
`docs/hackathon/deliverables/track1_model_y_v3/`: 18 OPM-пересчётов,
январь–июнь 2014. После исправления границ периода: ЧДД 310,611425109 млн руб.
против базовых 310,403015756 млн руб.; прирост +0,208409353 млн.
Старые абсолютные значения 361,956247531 / 361,747838179 включали лишний
исторический месяц и для КТ3 заменены исправленными значениями.
Это выбор среди трёх значений закачки одной скважины, без доказательства
глобальной оптимальности.

Новый режим сокращает число полных OPM-пересчётов до одного на месяц.
Суррогат для выбора не используется. Экономическое превосходство выбора LLM
над перебором или baseline не гарантируется. Без `--agent` сохранён прежний
детерминированный перебор всех заданных кандидатов.

Проверка 8 сентября: 178 тестов и 9 subtests прошли на A100, 2 проверки
пропущены; сборка Docker, `/health`, `/v1/capabilities`, compileall и импорт
пакета прошли. Подтверждены 4 полных OPM-месяца с живым агентом; критик прошёл
первые 3, затем запрос LLM завершился ошибкой на апрельском review. Полная
шестимесячная агентная репетиция не завершена. Две отдельные попытки запуска
января на исправленном коде также остановились на LLM до OPM; причина
конкретного HTTP/транспортного сбоя не установлена. Короткие диагностические
запросы работали. После добавления диагностики отдельно прошли три роли
планирования на реальном январском контексте и планирование через сам CLI
до вызова OPM. Исходную ошибку эти проверки не воспроизвели; полную
шестимесячную репетицию они не заменяют. Автоматического повтора
LLM-запросов и возобновления прерванного цикла пока нет.

Расчёт запускался из `73704d9`; исправление периода проверено тестами
`b50607b` и отдельным пересчётом тех же хешированных OPM-экспортов. Первые
3 результата с исправленным ЧДД повторно одобрены живым критиком.
В новом коде ошибки LLM дополнены безопасным HTTP-статусом или типом ошибки.
Гарантия выполнения полного кейса за 45 минут пока не подтверждена.

[Комплект репетиции](hackathon/deliverables/track1_model_y_kt3/summary.json)
содержит точные границы проверки и исправленный ЧДД. Для старого кейса
сохранён прежний лучший OPM-проверенный график; он не выдан за победу нового
агента. Крупные исходные результаты и журналы сохранены на A100. По новым ограничениям и истории 11 сентября
нужен отдельный запуск и отдельные `wells_schedule.inc` / ЧДД только за период
управления AIOS. По полученному расписанию сдача Трека 1 — до 17:45;
репетиция на старом кейсе не гарантирует время выполнения нового кейса.
