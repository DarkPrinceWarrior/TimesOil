# Scorp — TimesOil, Трек 2

**[Передача: актуальное состояние, результаты и команды — 10 сентября](docs/HANDOFF_20260910.md)**

Репозиторий команды **Scorp**: прогноз Google TimesFM 3.0 на полный период
Model Z, поиск управлений по прогнозному ЧДД, фиксация выбора и **одна**
финальная проверка в OPM Flow с официальным ЧДД.

**[Подробный алгоритм обоих треков: данные → агенты → TimesFM → OPM → ЧДД](docs/ALGORITHM_TRACKS_1_2.md)**
— схемы, формулы, раскрываемые разделы, действия агентов и границы текущей
реализации. Полные учебные периоды: 23 месяца Y и 224 месяца Z. Точность
автономного прогноза Z и его UQ/OOD остаются незакрытыми.

## Рабочая цепочка Трека 2

```text
Model_Z_final_OPM.zip
 → банк сценариев OPM (базовый прогон, канонический экспорт, полные 224 месяца)
 → связность INIT/EGRID → connectivity.json
 → обучение Google TimesFM (девять экономических выходов, полный backbone)
 → оценка на закреплённом наборе с неизменным разбиением
 → поиск: сетка + раунды Qwen, официальный калькулятор по прогнозным рядам,
   ограничения собственных заданий скважин → фиксация выбора
 → ровно один финальный OPM + официальный ЧДД → парный аудит
```

Внутри поиска нет вызовов OPM. Прогнозный ЧДД не является официальным:
официальным считается только результат калькулятора организаторов на выходе
OPM при сопоставимой парной базе. После финального физического результата
выбор другого графика запрещён.

Qwen не подменяет численные ворота: он предлагает и критикует. Валидатор
ограничений, симулятор и калькулятор ЧДД остаются детерминированными.

## Что реализовано

- совместный прогноз TimesFM 3.0 на 103 скважины и 224 месяца с плановыми
  управлениями, геологией и связностью;
- девять экономических выходов прогноза → таблица официальной экономики;
- генерация воспроизводимого банка сценариев управления и режимов BHP;
- последовательные прогоны сценариев в OPM Flow с проверкой происхождения входов;
- поиск графика по прогнозному ЧДД с ограничениями собственных заданий скважин
  и криптографической фиксацией выбора до единственной финальной проверки;
- расчёт ЧДД официальным Python-калькулятором и парное сравнение полного периода;
- AIOS с четырьмя ролями: координатор, инженер по разработке, планировщик, критик;
- внешний Qwen `qwen3.8-27b` через API Татнефти; локальная LLM не используется;
- Docker-образ API и конфигурация запуска.

## Быстрый запуск

Требования: Python 3.13, `uv`, Docker и образ OPM Flow, указанный в
`docs/RUNBOOK.md`.

```bash
uv sync --locked
uv run python -m compileall -q src scripts
uv run pytest tests -q
uv run timesoil-aios doctor
```

API:

```bash
cp config/aios.example.env config/aios.env
# проверить маршрут Татнефти в config/aios.env; API-ключ хранить отдельным файлом
mkdir -p secrets && chmod 700 secrets
printf '%s' "$QWEN_API_KEY" > secrets/qwen_api_key
chmod 600 secrets/qwen_api_key
docker compose --env-file .env.example up -d --build --wait --wait-timeout 180
curl --noproxy '*' --fail http://127.0.0.1:8000/health
curl --noproxy '*' --fail http://127.0.0.1:8000/v1/capabilities
```

Операторский веб-интерфейс поднимается тем же контейнером и доступен по адресу
`http://127.0.0.1:8000/app/`; статика лежит в `frontend/` и копируется внутрь
образа. Данные расчётов интерфейс читает через API `/v1/results`: каталог
результатов хоста (по умолчанию `./results`, переопределяется переменной
`TIMESOIL_RESULTS_DIR` в `.env.example`) монтируется в контейнер только на
чтение как `/app/results`, и туда же указывает `TIMESOIL_RESULTS_ROOT`.

Compose использует минимальный bootstrap с правами только на чтение секрета и
смену UID/GID. Перед запуском API он сбрасывает capabilities и переходит на
UID/GID `10001`; сам API от root не работает.

Остановка без удаления сохранённых расчётов:

```bash
docker compose --env-file .env.example down
```

Расчёты, обучение и финальная проверка запускаются по инструкции в
`docs/RUNBOOK.md`: исходная модель и крупные результаты в Git не входят.
Единый операторский запуск внешнего Qwen → OPM Flow → канонический экспорт →
ЧДД выполняется командой `timesoil-aios full-cycle`; точный контракт запроса,
переменные окружения, коды завершения и fail-closed условия приведены в
разделе 7 `docs/RUNBOOK.md`.

JSON в `deliverables/track2_model_z/` — публичные сводки с ограниченными
утверждениями, а не самостоятельные криптографические квитанции. Они не заменяют
`full-cycle-receipt.json` и связанные с ним хешированные манифесты запуска.
