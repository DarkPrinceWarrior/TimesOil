# Scorp — TimesOil, Трек 2

**[Передача Claude Code: актуальное состояние, результаты и команды — 10 сентября](docs/HANDOFF_CLAUDE_CODE_20260910.md)**

Репозиторий команды **Scorp**: прогнозы Google TimesFM 3.0, поиск управлений
и обязательная проверка графиков в OPM Flow с официальным ЧДД полного периода.
CRM + LightGBM сохранён как отдельный сравнительный контур.

**[Подробный алгоритм обоих треков: данные → агенты → TimesFM → OPM → ЧДД](docs/ALGORITHM_TRACKS_1_2.md)**
— схемы, формулы, раскрываемые разделы, действия агентов и границы текущей реализации.
Полные учебные периоды: 23 месяца Y и 224 месяца Z; короткий прогноз остаётся
предварительной оценкой. Полный автономный оптимизатор TimesFM ещё не подтверждён.

## Что реализовано

- совместный прогноз TimesFM 3.0 с плановыми управлениями, проверка 23/224 месяцев
  и предварительная оценка политик Qwen; ограничения качества описаны в алгоритме;
- генерация воспроизводимого набора сценариев управления;
- последовательные прогоны сценариев в OPM Flow с проверкой происхождения входов;
- суррогат `CRM/material balance + ансамбль LightGBM по остаткам`;
- адресная закачка, давление соседей и геологические признаки Model Z;
- раздельные метрики на обучающей и тестовой выборках и оценка неопределённости;
- поиск управлений добывающих скважин и ограниченного перераспределения закачки,
  ограничениями по выходу за область обучения и финальным повторным расчётом
  в OPM Flow;
- расчёт ЧДД официальным Python-калькулятором;
- AIOS с четырьмя ролями: координатор, инженер по разработке, планировщик,
  критик;
- внешний Qwen `qwen3.8-27b` через API Татнефти; локальная LLM не используется;
- Docker-образ API и конфигурация запуска.

## Сохранённый обучаемый контур CRM + LightGBM

```text
управления → генератор сценариев → OPM Flow → канонический датасет
           → геология + обучение → поиск добычи и закачки → OPM → ЧДД периода
                                      ↑
                         Qwen/AIOS предлагает и критикует
```

Qwen не подменяет численные ворота: он формирует рекомендации. Симулятор,
валидатор ограничений и калькулятор ЧДД остаются детерминированными.
Перераспределение включается явно через `--perturb-injection` и требует
межскважинной модели. Старый артефакт КТ2 загружается в прежнем режиме.

## Структура

```text
src/timesoil/aios/   AIOS, OPM, экономика, суррогат и поиск
scripts/             генерация, прогоны, обучение и финальный replay
tests/               контрактные и численные проверки
docs/                алгоритм, приёмка, ограничения и инструкция оператора
config/              пример конфигурации без секретов
deliverables/        публичные ограниченные сводки результатов
```

## Быстрый запуск

Требования: Python 3.13, `uv`, Docker и образ OPM Flow, указанный в
`docs/RUNBOOK.md`.

```bash
uv sync --locked
uv run python -m compileall -q src scripts
uv run pytest tests -q
uv run timesoil-aios doctor
```

API:

```bash
cp config/aios.example.env config/aios.env
# проверить маршрут Татнефти в config/aios.env; API-ключ хранить отдельным файлом
mkdir -p secrets && chmod 700 secrets
printf '%s' "$QWEN_API_KEY" > secrets/qwen_api_key
chmod 600 secrets/qwen_api_key
docker compose --env-file .env.example up -d --build --wait --wait-timeout 180
curl --noproxy '*' --fail http://127.0.0.1:8000/health
curl --noproxy '*' --fail http://127.0.0.1:8000/v1/capabilities
```

Compose использует минимальный bootstrap с правами только на чтение секрета и
смену UID/GID. Перед запуском API он сбрасывает capabilities и переходит на
UID/GID `10001`; сам API от root не работает.

Остановка без удаления сохранённых расчётов:

```bash
docker compose --env-file .env.example down
```

Обучение и повторный расчёт запускаются по инструкции в `docs/RUNBOOK.md`: исходная
модель и крупные результаты в Git не входят.

Единый операторский запуск внешнего Qwen → OPM Flow → канонический экспорт →
ЧДД выполняется командой `timesoil-aios full-cycle`; точный контракт запроса,
переменные окружения, коды завершения и fail-closed условия приведены в разделе
5 `docs/RUNBOOK.md`.

JSON в `deliverables/track2_model_z/` — публичные сводки с ограниченными
утверждениями, а не самостоятельные криптографические квитанции. Они не заменяют
`full-cycle-receipt.json` и связанные с ним хешированные манифесты запуска.
